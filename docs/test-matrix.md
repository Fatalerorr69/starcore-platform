## Legend

- **Unit** — pure logic, no I/O, no FastAPI/DB fixtures.
- **Integration** — exercises real collaboration between modules (FastAPI
  `TestClient`, a real (test) database session, the actual provider
  registry).
- **Smoke** — "does the whole thing start and respond at all" — CLI entry
  points, `/health`, container startup, documentation build.
- **Security** — regression tests specifically protecting an
  authentication, authorization, or information-disclosure invariant.
- **Property-based** — Hypothesis-driven, asserting an invariant across a
  generated range of inputs rather than a single fixed case.

## Notably *not* covered by an automated test (by design)

- **Docker image content/size** is not asserted by a test (e.g. "bandit
  must not be present") — the CI `docker-build` job builds and smoke-tests
  the real image, which is the meaningful signal; asserting exact package
  presence would be brittle and low-value.
- **Real Proxmox/Docker daemon behavior** is never exercised — every
  provider test uses a fake/mock provider or mocks the underlying SDK
  client, by design (`CLAUDE.md`: "a test suite that mocks external
  systems appropriately rather than requiring live infrastructure").
