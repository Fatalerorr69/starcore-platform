## 4. Implemented Changes (chronological, matches commit history)

1. **`fix(orchestrator): enforce dependency failure semantics (ADR-010)`** — `TaskStatus.SKIPPED_DEPENDENCY_FAILED`; `Scheduler` and `BlueprintExecutor` both gate dispatch on every dependency having reached `SUCCESS`, propagating transitively across waves/diamonds. `ExecutionPlanner.create_plan()` now threads `depends_on` through the flat plan so the sequential path has the information to enforce this. **Behavior change**, deliberate: a blueprint run where an upstream resource fails will now correctly report downstream resources as `SKIPPED_DEPENDENCY_FAILED` instead of silently attempting (and possibly "succeeding" at) them.
2. **`test(security): centralize secret redaction...`** — `packages/core/security.py` (`redact_database_url()`, `scrub_configured_secrets()`); applied to Proxmox/Docker provider connect/health exception paths; `tests/test_security.py` adds a regression sweep proving no unauthenticated response leaks a synthetic configured password.
3. **`docs(architecture): document plugin trust boundary; fix(cli): remove dead --non-interactive flag`** — `docs/plugins.md`; removed `--non-interactive` from `doctor`/`audit`/`diagnose` (never had any interactive behavior to control).
4. **`docs(architecture): add ADR-010/011/012, CLI/API/security reference pages`** — three new ADRs; `docs/cli.md`, `docs/api.md`, `docs/security.md`.
5. **`docs(development): document the Alembic downgrade/rollback procedure`**.
6. **`fix(docker): multi-stage build, drop dev deps and runtime PyPI dependency`** — see §14 for the verification method (a live Docker daemon was actually available and used).
7. **`ci: add mkdocs build --strict gate; docs: add test matrix`** — `docs/test-matrix.md`; new CI step.
8. **`docs: sync CLAUDE.md and README with this sprint's changes`**.

## 15. Breaking Changes

1. **Dependency-failure semantics** (ADR-010): a blueprint run where a
   resource fails now reports its dependents as `SKIPPED_DEPENDENCY_FAILED`
   instead of attempting them. Any external tooling that parsed task
   status strings and only expected `pending`/`running`/`success`/`failed`/
   `skipped` needs to handle the new value.
2. **`--non-interactive` removed** from `starcore doctor`/`audit`/
   `diagnose`. Any script passing this flag will now get a Typer "no such
   option" error. It never changed behavior, so the fix for any affected
   script is simply to stop passing it.
3. **`STARCORE_AI_MODEL` required for the `openai-compatible` AI
   provider** — pre-existing from an earlier sprint (not this cycle),
   documented in CLAUDE.md as part of this cycle's doc sync; noted here
   for completeness since it is a breaking config requirement.

No API route, response schema field, or database column was removed or
renamed.
